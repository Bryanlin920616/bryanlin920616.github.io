## 前言

我在申請過程中，從每年的心得文了解如何申請，幫我省下昂貴的代辦費。希望能繼續傳承下去，供未來想留美的人參考，也作為自己成長過程的一個紀錄。

我萌生留學的想法是在大一的時候。當時參加為期六個月的 coding bootcamp，發現寫程式滿有趣的，又看到人手大廠 Offer，就有想出國的念頭，也在大二轉到資工系。

不過接續的大裁員和 AI 對產業的影響，有讓我有點動搖開始拼趴數搞推甄。最後仍決定要出國的理由是，我不想不清楚方向 / 興趣就唸一個要做研究的碩士，只為了進台灣科技業領更高的薪水。這樣被注定的未來讓我有點不安，也不禁思考人生的意義。

我從小到大就是個阿宅，喜歡打球、打電動，家裡也沒有出遊的習慣。如果未來的人生也是這樣，沒有機會探索這個世界，就太可惜了。就算在美國的日子不順利，也至少是我親自走過的。

不過我也是有想過最壞的打算，大概是回台灣做還可以的工作，住在家裡慢慢還家人錢，大概五年可以把錢還完，然後沒錢買不起房這樣。不知道為什麼感覺沒有很嚴重，就覺得要衝了，謝謝爸媽給我的底氣 xd

## 選校策略

我到了 6 月托福一戰完才有空做初步的選校，以下是我的選校過程。

1. **列申請清單**：可以參考 Dcard 選校文、申請結果串，再看 opencs, csgrad 有沒有遺漏的也加進來。這個階段可以多列一點。
2. **搜集資料**：查各個 Program 的就讀心得、官網，把各種資訊記錄下來。如果滿確定要申請的，也可以先紀錄要準備哪些文件、檢定門檻等資訊。
3. **調整申請清單**：根據搜集的資料對清單標註、排梯度，然後挑出最後的申請清單。

我幾乎沒有研究經歷，未來也沒有做研究的打算，所以我只申請修課型、就業型的 Program，且幾乎都有軟體課可以上，例如 Distributed Systems, Database Systems, Cloud Computing。

在看 opencs, csgrad, 一畝三分地的時候，不用太擔心怕申請不上就不投，因為兩邊的 pool 不同，難度也不同。可以多看看台灣學生的申請結果做參考。

各個區間的比例，我覺得夢幻、衝刺可以多投一點，選一些上了真的會想去的，而保底有一兩個就好了。CMU 的 Program 真的很多、有各種 CS 下的分支，可以選跟自己背景符合的投。

### 一些我自己的 Program 觀察

- **Rice, UIUC, Columbia**：感覺都是 rolling-basis，準備好了就早點投，發很多人 Offer，有投有機會。
- **CMU ECE**：也發不少，有一部分人會被 defer 到 Spring。
- **CMU MSIN**：重文書，有辦講座教你怎麼寫文書，還可以 waive 申請費。分兩輪發 Offer，我是 Priority Round，所以很早就收到 Offer 了，也建議可以早點投，不知道獎學金金額有沒有影響。
- **UT ECE (SES)**：依然非常競爭，恐怕要大廠實習 + 研究經驗豐富才有機會。
- **UWM CS PMP**：喜歡工作經歷很豐富的，只有實習也至少要是知名大廠。
- **Yale MSCS One-Year, Cornell CS MEng**：因為不能實習、找工壓力大，比較少人投也沒那麼競爭，多數是美本多段大廠實習或是 0 經驗計畫回國的。
- **UW ECE PMP**：找工神 Program，聽說可以做好多段全球 Coop。近年來常被跟 UIUC, UCSD 一起比較，但選課有一點點受限。
- **UCSD MSCS**：標準很玄，就當抽獎。
- **GT CSE**：有幾門數學課要修，對選課在意的可以想想。但好像跟 MSCS 找工沒區別，且學費低 CP 值高。
- **Duke ECE Software track**：課程滿不錯的，聽說也滿紮實的，對找工有幫助。
- **Purdue MSCS**：系統課紮實、學費非常便宜、地點很偏。

## 申請文件

### SoP

當時看了很多篇心得文，但還是不知道怎麼開始。以下提供我撰寫的順序流程，可以一步步來。

#### 撰寫流程

1. 列出大學課內課外經歷，把每段經歷的內容寫下，可以很鉅細靡遺。
2. 公版初稿：想好架構、脈絡，把整理的經驗放進去，這時候中英文夾雜也沒關係。
3. 公版第一版：統一英文版，確保專業用語使用正確，去除空洞、AI 感內容，加強整體脈絡，讓每個段落環環相扣。Optional：潤稿。
4. 一間間做客製化。

#### 格式

2 pages, ~800 words, Times New Roman (12 pt), Letter size, 1" margins.

#### 架構

```text
---Page 1: Experience---
[Hook]
從 clean code → scalable / reliable systems，帶出申請動機：
想補足 distributed systems / software architecture 的理論基礎。

[專題] Learning Through Challenges.
從 ML application 的 latency / computation / deployment trade-off，
引出對 low latency、scalability、system design 的興趣。

[實習] Observing Architectural Paradigms in Practice.
從新創與企業實習中的後端開發經驗，
觀察不同系統架構在 deployment、scalability、consistency、simplicity 上的取捨，
進一步確認自己想深入學習 distributed systems 與 software architecture。

---Page 2: Program fit---
[Why this Program] Why xxx's MSCS Program.
1. 課程：distributed systems、OS / networking、database、cloud、software engineering。
2. 研究：教授 / Lab / project，適合 MSCS 或偏研究型 program。
3. Program 特色：industry connection、career resources、internship flexibility、
   tech hub / location、alumni network。

[結尾] Future Vision.
總結上述經驗、自薦，列出短期、長期目標。
```

#### 註記

- 我有用 Topic Sentence 來切分段落，讓文章更有組織點。不然專題、實習、Why 分別都有兩段，我自己閱讀覺得有點亂。
- 如果跟我一樣都是寫應用軟體的 web, app, backend，在查教授研究內容及讀 Paper 的時候，會發現 Application & System level software 做的內容差異是非常大的，也很難跟自己的經歷做關聯。所以到申請後期能不寫這段就不寫，很費時又太牽強。最後有寫的只有 UWM, UCSD, UT, Purdue，四間爆了三間，但我感覺不是這個原因。

#### 小心得

CMU MSIN 是沒有 SoP 的，取而代之的是 Essays，其中有一題問的是：

> Why do you consider yourself to be a strong candidate? What sets you apart from other applicants? e.g. CTFs, programming competitions, or hackathons, published peer-reviewed research, significant awards

當時看到就覺得自己沒機會了。然而 INI 講座有一句讓我印象很深刻的話是：

> you're kind of connecting the dots for them to understand what you're saying

不要覺得自己的經歷不起眼，把你最好的一面自信地展現出來就好！

如果沒有要求 PS 或任何 Integrity related questions，可以考慮在 SoP 裡面加一點點多元色彩做點綴，比如某個 Project / Research 是為了救濟貧窮、彌平教育差距等。小小帶過就好，沒有關聯的話就不要硬加。我個人是沒有加，但像是前面說的那題我就有提到英文志工的事。

AI 詞句很容易空洞和加油添醋，反覆閱讀的時候要多懷疑，不要順順念過覺得合理就接受它了。避免出現太多破折號；在講省思 / 領悟 / 心路歷程的段落時，也避免自問自答的引導方式，直接講體悟到的事就好了。

可以在 Experience 段落鋪墊不足之處，而在 Program fit 的地方各種呼應，來加強你跟 Program 適配程度！

我在專題、實習段落的脈絡是從過去經驗，到意識到不足，再到申請動機。這邊用詞盡量保持正向，不要太貶低自己。

[Bear Tien](https://medium.com/@stitch.hsiung)：「你不需要很強，但你需要很適合！」在寫 SoP 文件時可能會多次懷疑自己，當時看到這句覺得有被鼓勵到。背景、經歷有不足的地方很正常，這也是寫文件該有的心態：你不一定是最強的，但要展現出你是最適合的！

### PS

我申請的 Program 中多數都是用額外一兩題提問的方式，只有 Duke, Cornell, Purdue 有獨立上傳一份 PDF。先準備好公版對後續回答也有幫助。

大家對於 PS 的評價不一，我個人認為還是值得花些心力把故事說好。如果你足夠優秀的話可能沒差，但當你在錄取邊緣時，可能真的因為這些故事讓 Admission Committee 認為你是一個更完整的候選人而錄取你。

我的公版大致分成三個故事。

#### 從籃球與個人挫折切入專題動機

從籃球為興趣出發，談到自己的抗壓能力，再到受傷後不能打球的個人健康問題轉換成解決他人問題的動力。同樣是專題，但切入角度以動機跟目的為主，而非技術。

#### 教育資源落差到英文家教志工

從生長環境沒有補習資源出發，理解教育資源不平等帶來的差距。擔任英文家教志工，幫助同樣資源有限的學生。主要想呈現我對 accessible technology / inclusive learning 的重視，也強調我希望未來能持續幫助不同背景的人。

#### 從 Workshop 經驗展現跨文化合作

疫情期間參加一個 Virtual Workshop，有德國、喬治亞的學生。我從成員間不同文化背景下的不同做事風格切入，說明我怎麼在這樣的環境跟團隊中達成互補，證明自己的合作與溝通的能力。

### LoR

關於如何詢問推薦意願以及進度追蹤，大推 [Bear Tien 的文章推薦信段落](https://medium.com/p/b8e201d82486#6688)。怎麼擬稿則建議先看 [MIT 的這篇文章](https://mitadmissions.org/apply/parents-educators/writingrecs/)，我在看完之後得到很大啟發和幫助。

#### 推薦人配置

我總共投了 16 間，指導教授 16 封、實習主管 16 封、兩位授課教授各 8 封。

#### 找推薦人前先想好的事

在找推薦人之前，我有先想好每位推薦人可以推薦的內容與面向，並排好心中的志願序。這樣如果教授不同意，或是可撰寫的數量不夠，才好找下一位候選人詢問意願；也可以在詢問意願的時候一併告知推薦信數量與安排。

先想好推薦內容，也能確保這會是一封有說服力的信。如果發現自己跟推薦人的關係不夠緊密，或許就該找別位推薦人了。以下是當時詢問授課教授的信件供參考，需注意所有內容都要基於事實並且發自內心！

#### 詢問推薦意願信件範例

```text
教授您好，我是今年資工系的畢業生 XXX

[說明跟教授間的關係和表達感謝]
曾在 112-2, 113-1 修過教授的「機器視覺」和「人工智慧」，分別獲得 98, 96 的成績，

如需進行面談，看是教授您的辦公室還是線上討論比較方便，再隨時跟我說。

另外，因為預計申請 15 間學校的 18 個 Program，
```

#### 推薦信草稿架構

擬稿部分如果沒頭緒，可以先從修課成績、課堂表現、office hour 互動、project 中扮演的角色、遇到的困難開始發想。推薦信最重要的是要有實際互動的故事，讓推薦人對你的評價有具體例子佐證，而不是只有空泛的形容詞。

以下是我自己在整理草稿時使用的大致架構。

**第 1 段：Opening / Relationship + Overall Evaluation**  
說明推薦人身份、和你的關係、修過哪些課 / 認識多久，並先給整體評價。

**第 2 段：第一個具體例子 + 對應特質**  
例如課堂表現、修課成績、office hour 互動、主動學習、幫助同學等。

**第 3 段：第二個具體例子 + 對應特質 + Graduate Fit**  
例如專題、課堂 project、競賽經驗、實習工作內容等。

**第 4 段：Closing**  
總結推薦，說明你適合 graduate program，並歡迎學校聯繫。

### CV / Resume

我是直接拿找實習的履歷來用，這部分沒有什麼心得可以分享，照著經典的模板改成自己的內容就好。唯一頭痛的是量化數據的部分，可以適當地評估合理的數字放上去。

動詞盡量精簡，不要 AI 給出很華麗的字就直接用。我常用的動詞是 built, implemented, designed, contributed, developed, refined。盡量寫清楚自己實際負責的部分，例如你負責設計、實作、優化了什麼，而不是只寫參與或協助。這樣比較能表達你對這段經歷有 ownership，而不是只是跟著做。

額外分享的是我後來不用 Overleaf 了，因為 debug 太慢又沒時間學語法。非常推薦在本地編譯搭配你的 Codex / Claude Code 編輯（[Mac + VSCode + LaTeX 教學](https://zhuanlan.zhihu.com/p/654720622)），還可以用 git 做版控，再寫個 Makefile 用 Docker 跑，這樣跨裝置環境的問題也解決了。

### Video essays

總共有四所 CMU MSIN, CMU MSSE, Duke MSECE, Columbia MSCS 有要求 video essays。因為我英文口說比較弱，一開始對這部分滿擔心的，但實際做完覺得不用太害怕。

可以整理一畝三分地、小紅書的面經，幾乎全是 Behavioral 的問題。我遇到的都是看過的題目，可以準備幾個通用的 Story bank，幾乎可以覆蓋到所有的題目。

進行的方式：Portal > 彈窗測試 > 正式答題（文字 or 語音題目）。慢慢講，保持自信，不要緊張就行了。回答完就可以提早結束。總之這部分只是要測試你是個正常人會說英文而已，個人認為對申請幾乎沒有影響。

## 心得與致謝

感覺今年身邊認識的人、網路上的申請結果都挺好的，受惠於川普在搞簽證、險峻的就業市場勸退了很多人。但就算上的學校更好了，環境卻沒有當年好了，不知道該說好還是不好了。

錄取結果出奇的好，心情可說是五味雜成。很開心可以到世界頂尖大學讀書，但也擔心自己能否適應一個身邊的人都如此優秀的環境。不過他敢錄取我我就敢去念，用爬的也要爬到畢業然後上岸。不過大學把身體搞壞之後，覺得沒有比身體健康更重要的事了，希望在匹茲堡找到課業、找工、生活的平衡。

完全能理解申請結果好的才會出來寫心得，有人會說倖存者偏差。但我從大一就開始讀前輩們的文章，總算也輪到我當倖存者了。為什麼他們能成功一定有他的道理在，只有多看然後 fake it till you make it，接下來的日子也要一直倖存下去！

最後，謝謝爸媽支持我留學的決定，作為我跨出這步最大的後盾；謝謝郭老專題收留我，總是有求必應效率超高；謝謝前前主管 Kenny，我面試一團糟還錄取我，讓我有第一份工作經歷；謝謝好兄弟 Aiden 幫內推第二份實習；謝謝前主管 Peter 幫我寫推薦信；謝謝 Prof. Lin, Prof. Wang 幫我送兩次推薦信；謝謝 [Po-Lin (Berlin) Chen](https://medium.com/@berlinnn3388) 大大幫看履歷和 SoP！
